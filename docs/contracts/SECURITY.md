# Security Contract (Enforced)

## Trust posture

- Preserve local-first privacy guarantees.
- Minimize extension permissions and enforce explicit consent.
- No hidden remote calls in "local-only" flows.

## Electron hardening

Electron hardening that must not regress (renderer runs user markdown + arbitrary webviews, so the main process is the trust boundary):
- **`nodeIntegration: false`** on every BrowserWindow (`electron/src/setup.ts`). The renderer reaches main only through the `preload.ts` contextBridge; it never needs Node. Do not flip this on.
- **`contextIsolation: true`** stays on for every window.
- **`sandbox: true`** on every BrowserWindow. This requires the preload (`build/src/preload.js`) to stay a single self-contained file whose only `require()` is `electron` — no relative `require`, no Node builtins (`fs`/`path`/`crypto`). The Capacitor platform marker is inlined and the terminal-enabled flag comes from main via `terminal:enabled:getSync` for exactly this reason. If you must add a Node/relative dependency to the preload, bundle it (esbuild) first or sandbox breaks silently (renderer loses `electronAPI`).
- **No inline scripts in `index.html`.** Production `script-src` omits `'unsafe-inline'` (dev-only for Vite HMR). Entry-time scripts go in `main.tsx`/unit blocks (e.g. `iphoneViewportBlock.ts`), never inline `<script>`. After touching HTML/CSP, verify `dist/index.html` has zero `<script>` (only the external module).
- **Every vault-scoped IPC handler** validates the renderer `vaultRoot` via `assertAuthorizedVaultRootBlock`/`resolveInsideVaultBlock` (`vaultPathGuardBlock.ts`) — never trust a renderer path.
- **`vault:git`** only runs an allowlisted set of subcommands and rejects leading git global options (`-c`, `--exec-path`); don't widen it to pass arbitrary args.
- **Outbound network bridges** stay host/target-restricted: Webull + Google use host allowlists; `net:fetchText`/`net:fetchBytes` reject loopback/link-local/private targets (SSRF guard `assertPublicFetchUrlBlock`), including on redirects.
- **The reader's ad blocker stays in the reader** (`readerAdblockBlock.ts`, 2026-10-23). Ghostery's engine is enabled only on sessions whose partition starts with `persist:thinking-space-links` (attached on `will-attach-webview`); no other session is touched. Its only network use is fetching Ghostery's prebuilt filter lists from its CDN in main, cached in `userData/reader-adblock/` and refreshed when over a week old. The reader view fetches article pages through the existing `net:fetchText` (public hosts only) and renders only the text of the extracted paragraphs — never the page's HTML.
- **`vault:listFileStats`** (2026-10-23) lists a vault folder's files with mtime and size, under the same `assertInsideVault` validation as `vault:list`; no content, hidden files skipped.
- **The earnings call bridge never takes a URL** (`earningsCallsBlock.ts`, 2026-10-23). `earningsCalls:list` takes a ticker (`[A-Z][A-Z0-9.-]{0,9}`); `earningsCalls:get` takes a ticker and a call id from its list (`\d{1,9}-q[1-4]-20\d{2}`). Main builds every URL on `stockanalysis.com` only (public pages, no login), paces requests, and returns plain text.
- **The library bridge never takes a URL or sees a secret** (`librarySessionBlock.ts`, `libraryGaleBlock.ts`, `libraryValueLineBlock.ts`, 2026-10-23). `library:galeSearch` takes a publication from a fixed allowlist, a database (`STND`/`ITOF`), a day and 1–4 lowercase words; `library:galeArticle` takes a Gale document id (`[A-Z0-9]{6,24}`); `library:valueLineIssues` takes a ticker (`[A-Z][A-Z0-9.-]{0,9}`); `library:valueLineReport` takes a ticker and an issue date, and main looks up that issue's report key itself (the keys never reach the renderer). Main builds every URL itself, on the library proxy's hosts only, and runs on its own `persist:library` session. The card and PIN come from Settings → Webull → Library login (`libraryCredentialStoreBlock.ts`: safeStorage, mode 0600, the same pattern as the Webull keys; `library:saveCard` / `library:clearCard` are write-only) or, when none is saved, from the macOS Keychain (`atxlibrary-austin`) read by `/usr/bin/security` with `cwd` pinned to the vault. They are used only for the proxy's login form and never returned to the renderer (`library:status` gives the source and a masked card, `…1234`). Requests are serialized and paced. Do not add a URL or a credential to these payloads.
- **The option-chain bridge never takes a URL** (`yahooOptionsBlock.ts`, 2026-10-27). `market:optionChain` takes a ticker (`[A-Z][A-Z0-9.-]{0,9}`) and optionally an expiry as whole seconds; main builds every URL itself, on Yahoo's hosts only, in its own in-memory session (`yahoo-options`, never the default one), where Yahoo's cookie and crumb stay. It returns only prices, the quote's market time, market value and P/E from the same quote, expiry dates and per-strike call quotes. Requests are serialized and paced. Do not add a URL or headers to its payload.
- **Webview `connect-src`/CSP** and the webview permission allowlist (`setupWebviewSessionPermissions`) stay narrow; new outbound origins go through `cspWhitelistBlock.ts`, not a broadened template.
- **Vault HTML pages are served one folder at a time** (`vaultHtmlPageBlock.ts`, approved 2026-10-08). A `.html` file loads in a `<webview>` from `<app scheme>://page-<hash>/…` on the dedicated `persist:thinking-space-html-pages` partition; the handler serves only the page's own folder and below (lexical + realpath containment), and only for folders minted through the path guard via `vault:htmlPage:url`. Page scripts are untrusted and have network access, so the served folder is exactly what a page can exfiltrate — do not widen it to a parent or the vault, and do not register this handler on the app's session.
- **Outside Electron, a vault HTML page never shares the app's origin** (`HtmlDocumentBlock.tsx`, 2026-10-16). Web and iOS render it in an iframe from a blob URL, which inherits the app's origin, so the sandbox must not include `allow-same-origin`: with it the page's scripts could read the app's IndexedDB — including a browser vault's directory handle, i.e. the whole vault — and send it anywhere. Scripts still run, under an opaque origin.
- **EPUB content never runs script** (2026-10-20). foliate-js renders sections from blob: URLs (the app's origin) in iframes that must carry `allow-same-origin allow-scripts` — WebKit drops events otherwise — so the sandbox blocks nothing. `EpubDocumentBlock` refuses script resources at load and runs every section through `guardEpubMarkupBlock` (strip script/handlers/javascript: URLs/embeds, then inject a `script-src 'none'` CSP meta as the first `<head>` child) before it becomes a blob. A book whose loader exposes no `transformTarget` hook is not opened. Do not render book markup any other way.
- **The static web build talks only to its own origin and holds no secrets** (2026-10-16). In a browser the page is the only trust boundary, so `PAGES_CSP` (`vite.config.ts`) allows `connect-src`/`img-src`/`frame-src` to `'self'`, `data:` and `blob:` only — a script that gets in cannot send the vault anywhere. Do not add an outside origin to it; a feature that needs one stays out of that build (`staticWebBuildBlock.ts`). API keys and OAuth tokens are never written to or read from its storage (`storageKeyBlock.ts`).
- **Vault files that become markup are validated before any string is built** (`excalidrawPreviewBlock.ts`, 2026-10-16). The Excalidraw preview assembles SVG as a string and inserts it with `innerHTML`, so a drawing is untrusted input: every number field must be a finite number and every text field a string before it reaches a template; text is XML-escaped. A string in a number field (`"strokeWidth": "1\"/><image onerror=…>"`) was enough to run script in the app with vault access. Any new string-built markup from vault content follows the same rule, or uses DOM APIs instead.
- **The app window never leaves the app document, and outside files enter only through the vault check.** `will-navigate` refuses a same-scheme navigation to any other path (`appNavigationGuardBlock.ts`) — plain markdown links are routed by the viewer, not the browser. A file handed over by macOS (`open-file`, used by `scripts/iterm-open.sh` and the `.md` file association) becomes a vault route if its real path is a regular file inside an open profile's vault (`externalFileOpenBlock.ts`). Otherwise, a regular `.md`/`.markdown` file is **granted on its own** (approved 2026-10-16): main records its real path for the app session and opens it by that absolute path; `externalFile:read`/`write`/`stat` serve only exact granted paths that still resolve to themselves. The OS hand-over is the consent — the renderer can never mint a grant, and there is no grant for a folder, a sibling, or a non-markdown file. Do not add a renderer-callable way to grant, and do not widen the vault IPCs to accept absolute paths.
- **The app writes to another program's config only on an explicit button, to fixed paths, and reversibly** (`claudeStatusLineConnectBlock.ts`, approved 2026-10-10). The one case is Claude Code's `~/.claude/settings.json`, where the "Connect Claude" button sets `statusLine`. The IPC (`ai:plan-usage:claude-connect` / `-disconnect`) takes **no arguments** — settings path, wrapper path and the bundled script are resolved in main, so the renderer can name neither a file to write nor a command to install. It never runs on launch or on a read. It **wraps** an existing status line rather than replacing it, **refuses to write over a settings file it cannot parse**, records what was there and copies the file aside before the first write, and writes temp-then-rename. Do not add a second such write without the same four properties, and do not make this one automatic.
- **Every child process must run with `cwd` pinned to the vault root** (fallback: userData / `~/.thinking-space`), never inherit the app's cwd (`/` when Finder-launched) or `$HOME`. macOS bills all file access by app-spawned children (claude CLI, scheduler runner agents, PTYs) to the APP's TCC identity — an unpinned child roaming from `/` or `$HOME` is what caused the "Thinking Space wants access to Desktop/Documents/Downloads/Network Volumes" prompt storm (fixed 2026-07-17: `claudeCliBlock.resolveChildCwdBlock`, `runner.mjs defaultExecutionCwd`, PTYs already pinned). The app's TCC prompt budget is exactly one: the vault folder. Related: TCC keys on bundle id + signing-cert leaf hash, so ad-hoc signing (pre-2026-07-16) reset all grants on every rebuild — the stable local cert in `checkpoint-ship.sh` must not regress.
